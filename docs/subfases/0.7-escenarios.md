# Subfase 0.7 · Escenarios de carga

> **Entrega:** [PR #5](https://github.com/NewHouses/meiga/pull/5).

## Obxectivo

Ter cargas de traballo reproducíbeis que imiten o uso real dun terminal, tanto nunha tab de PowerShell como nunha de Ubuntu (WSL), e un script que mida un terminal mentres corren e diga se os resultados son estábeis. Con eles farase a liña base co Warp e o Windows Terminal (subfase 0.8) e a porta de rendemento de cada fase.

Ademais, despois da subfase 0.6 decidiuse que os scripts seguen sendo só para PowerShell 7, pero que ese requisito ten que verse mellor: nas instrucións e cunha mensaxe que, en Windows PowerShell 5.1, mostra o comando exacto con `pwsh`.

## Decisións e alternativas descartadas

| Decisión | Alternativa descartada | Motivo |
|---|---|---|
| Cada escenario en PowerShell e en bash | Só en PowerShell | As tabs de Ubuntu chegan ao terminal por outro camiño, a través de WSL, e tamén hai que medilo. |
| | Un só script noutra linguaxe, como Python | Habería que instalala en Windows e en WSL. PowerShell e bash xa están. |
| As dúas versións debuxan exactamente o mesmo | Versións só parecidas | Así, a diferenza entre unha tab de pwsh e unha de WSL é a do camiño, non a da carga. |
| Coordinación con arquivos baleiros en `.perf/run/` | Rede, tubaxes con nome ou sinais | Os arquivos funcionan igual en Windows e en WSL, sen portos nin procesos extra, e pódense mirar co explorador. |
| `run-scenario.ps1` noutro terminal, mostrando o comando que hai que executar no medido | Que abra el mesmo a tab no terminal medido | Cada terminal abre as tabs á súa maneira, e non todos se poden controlar desde fóra. Así funciona con calquera, tamén con meiga. |
| 3 medicións seguidas de 60 s e un veredicto | Unha soa medición | Unha medición pode coincidir cunha actualización de Windows ou co antivirus. Se as tres se parecen, o resultado é fiábel. |
| Veredicto cos ciclos do terminal | Coa CPU, como se acordara ao deseñar a subfase | Windows conta o tempo de CPU en tics de 15,625 ms. Nas probas, a CPU dunha consola co spinner variou máis do triplo entre medicións, e os seus ciclos, menos dun 10 %. |
| En bigfile, veredicto co tempo de imprimir | Cos ciclos | O orzamento da saída masiva é de tempo: imprimir 50 MB polo menos tan rápido coma o Windows Terminal. |
| Fotogramas a momentos fixos | Esperar 0,1 s despois de cada fotograma | Windows esperta os fíos un pouco tarde, e os atrasos sumaríanse ata baixar o ritmo. |
| Unha soa escritura por fotograma | Escribir cada parte por separado | As ferramentas reais escriben o fotograma enteiro, e cada escritura pode provocar un redebuxado no terminal. |
| bigfile: un arquivo xerado, igual en calquera máquina | Un rexistro real | Un rexistro real non se pode publicar e sería distinto en cada máquina. A SHA-256 permite comprobar que o arquivo é o mesmo. |
| bigfile en WSL: copiar o arquivo a `/tmp` antes de empezar | Lelo desde `/mnt/c` | Ler o disco de Windows desde WSL é lento (protocolo 9P), e mediríase iso e non o terminal. |
| bash sen crear procesos mentres corre (o reloxo con `EPOCHREALTIME` e as esperas con `read -t`) | `date` e `sleep` | Cada proceso novo custaría máis que o propio fotograma, e mediríase bash e non o terminal. |
| Só PowerShell 7, cunha mensaxe en 5.1 | Que os scripts funcionen tamén en 5.1 | Decidíchelo ti despois da 0.6: en 5.1 fallaban a codificación dos CSV e a súa lectura con `Import-Csv`, e manter as dúas versións custaría máis do que achega. |
| Unha comprobación propia ao comezo de cada script | `#Requires -Version 7.0` | `#Requires` detén o script cunha mensaxe técnica que non di como executalo. |
| Os valores por defecto con `$PSScriptRoot`, despois da comprobación | En `param()` | En 5.1, `$PSScriptRoot` está baleiro nese momento, e o script fallaba antes de mostrar a mensaxe. |
| Os `.ps1` en ASCII, cos outros caracteres como `` `u{…} `` | UTF-8 con marca de bytes (BOM) | Bastaría con que un editor quitase a marca para que 5.1 lese mal o arquivo outra vez. En ASCII non hai nada que se poida perder. |
| Os escenarios de bash na CI, nun job de Linux | En Windows, con WSL | En Ubuntu, bash 5 e ShellCheck xa veñen instalados. En Windows habería que preparar WSL cunha distribución en cada execución. |
| ShellCheck coas regras por defecto | Con todas as opcionais (`-o all`) | As opcionais só engadían avisos de estilo. |

## Como comprobar que todo está ben

> **Importante: usa PowerShell 7.** Todos os comandos son para PowerShell 7 (`pwsh`), no cartafol do repositorio. Se abres *Windows PowerShell* (a versión 5.1, que trae Windows), os scripts non se executan: só mostran o comando para facelo con `pwsh`. Para saber cal tes aberto, executa `$PSVersionTable.PSVersion`: o primeiro número ten que ser 7.

### No navegador

1. **A CI pasa.** No [PR #5](https://github.com/NewHouses/meiga/pull/5), os tres *checks* en verde: **Build and test (Windows)**, **Load scenarios (bash)** e **Dependency policy (cargo-deny)**.

   **Resultado esperado:**

   - En **Build and test (Windows)**, o paso *Check that the scripts ask for PowerShell 7* remata con `OK: the 13 scripts ask for PowerShell 7, and Windows PowerShell 5.1 shows how to run them.`, e o paso *Check the load scenarios in PowerShell* mostra a táboa das comprobacións, todas en `ok`, e remata con `All 26 checks passed.`
   - En **Load scenarios (bash)**, o paso *Check the bash scripts with ShellCheck* só mostra a versión de ShellCheck, sen ningún aviso, e o paso *Check the load scenarios in bash* remata con `All 26 checks passed.`

### Na túa máquina

2. **Descarga a rama do PR:**

   ```powershell
   git fetch origin
   git switch f0.7-escenarios
   ```

3. **Comproba que os scripts piden PowerShell 7:**

   ```powershell
   .\tools\check-powershell.ps1
   ```

   **Resultado esperado:** despois duns segundos, `OK: the 13 scripts ask for PowerShell 7, and Windows PowerShell 5.1 shows how to run them.`

4. **(Opcional) Mira a mensaxe de Windows PowerShell.** Este comando executa un script con Windows PowerShell 5.1:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\perf\run-scenario.ps1 spinner WindowsTerminal
   $LASTEXITCODE
   ```

   **Resultado esperado:** en amarelo, `This script needs PowerShell 7. Run it with: pwsh -File .\tools\perf\run-scenario.ps1 <the same parameters>`, e despois `1`, o código de erro. Non se mide nada.

5. **Proba o arnés de medición:**

   ```powershell
   .\tools\perf\test-measure.ps1
   ```

   **Resultado esperado:** despois duns 25 s, a táboa coas 12 comprobacións, todas en `ok`. A nova é a última, `stop file: window, s`, cun valor entre 2 e 4. A última liña é `All 12 checks passed.`

6. **Proba os escenarios:**

   ```powershell
   .\tools\perf\test-scenarios.ps1
   ```

   **Resultado esperado:** en menos dun minuto, unha táboa con 52 comprobacións, todas en `ok`: 26 para PowerShell e 26 para bash, que corren en WSL. A última liña é `All 52 checks passed.` Se o teu WSL non ten bash 5, as de bash sáltanse cun aviso amarelo e só se fan as 26 de PowerShell.

7. **Mira o spinner:**

   ```powershell
   pwsh -NoProfile -File .\tools\perf\scenarios\spinner.ps1
   ```

   **Resultado esperado:** unha liña cun símbolo que xira e cambia de cor 10 veces por segundo, a palabra `Thinking` en negra e os segundos que leva, como `(12 s)`. Mentres corre, o cursor non se ve. Preme Ctrl+C: a liña queda como estaba, o cursor aparece de novo e o prompt sae na liña seguinte.

8. **Mira a IA:**

   ```powershell
   pwsh -NoProfile -File .\tools\perf\scenarios\ai-stream.ps1
   ```

   **Resultado esperado:** unha conversa cunha IA. Cada pregunta empeza por `❯`, en cian, e a resposta aparece palabra a palabra despois de 2 s de `Thinking…`, con cores, táboas aliñadas, emoji e caracteres chineses. Baixo o texto hai unha zona de estado de 3 liñas: o símbolo que xira con `Generating… (3 s · 87 words)`, unha liña horizontal e `ctrl+c to stop · simulated AI answer`. Despois da quinta resposta, a conversa empeza de novo. Con Ctrl+C, a zona de estado desaparece e o cursor aparece de novo.

9. **O mesmo en WSL.** Abre unha tab de Ubuntu e vai ao cartafol do repositorio, que en WSL está baixo `/mnt/c/` (o disco `C:`). Executa os dous escenarios, un despois do outro:

   ```bash
   bash tools/perf/scenarios/spinner.sh
   bash tools/perf/scenarios/ai-stream.sh
   ```

   **Resultado esperado:** exactamente o mesmo que nos pasos 7 e 8.

10. **Crea o arquivo grande:**

    ```powershell
    .\tools\perf\gen-bigfile.ps1
    ```

    **Resultado esperado:** despois duns segundos, `Created …\.perf\bigfile.txt: 52,754,910 bytes, 2000 lines repeated 146 times.` e `SHA-256: A36C2E71CBA56B9738DE79AE2533A24FEFA7CC293A426F9CF3A6ABC6074BFB13`. O tamaño e a SHA-256 son os mesmos en calquera máquina.

11. **Imprime o arquivo grande:**

    ```powershell
    pwsh -NoProfile -File .\tools\perf\scenarios\bigfile.ps1
    ```

    **Resultado esperado:** liñas de rexistro con cores, a toda velocidade, durante uns segundos. Ao final, `Printed 50.3 MB in … s.`

12. **Mide un terminal co spinner.** Necesitas dous terminais: o que mides e outro desde o que medir. Por exemplo, abre o Windows Terminal cunha tab de PowerShell 7 no cartafol do repositorio (o terminal medido) e, no Warp, executa:

    ```powershell
    .\tools\perf\run-scenario.ps1 spinner WindowsTerminal
    ```

    O script mostra o comando que tes que executar no terminal medido:

    ```text
    In the terminal that you measure, run this once:

        pwsh -NoProfile -File "…\tools\perf\scenarios\spinner.ps1"
    ```

    Cópiao, execútao na tab do Windows Terminal e deixa esa tab diante. Non toques nada ata o final, uns 3 minutos.

    **Resultado esperado:**

    - `Started: 1 of 1` en canto arranca o spinner. As medicións empezan 5 s despois.
    - Unha liña por medición: `Window 1 of 3: the terminal used … % of one core and … million cycles per second.`
    - A táboa do resumo, cos 8 grupos, e o veredicto. En verde, `Stable: the cycles of the terminal varied … million per second between windows (limit …).` Se sae en amarelo `Not stable`, a máquina estaba ocupada nalgunha medición: pecha o que poidas e repíteo.
    - `Saved …\.perf\scenario-…-WindowsTerminal-spinner.csv`.
    - O spinner do Windows Terminal remata só, como moito un segundo despois do resumo.

13. **Mide a IA nunha tab de Ubuntu:**

    ```powershell
    .\tools\perf\run-scenario.ps1 ai-stream WindowsTerminal -Shell wsl
    ```

    Agora o comando que mostra empeza por `bash '/mnt/c/…/ai-stream.sh'`: execútao nunha tab de Ubuntu do Windows Terminal.

    **Resultado esperado:** o mesmo que no paso anterior, co CSV `…-WindowsTerminal-ai-stream-wsl.csv`.

14. **Mide a saída masiva:**

    ```powershell
    .\tools\perf\run-scenario.ps1 bigfile WindowsTerminal
    ```

    Executa o comando que mostra nunha tab de PowerShell 7 do Windows Terminal.

    **Resultado esperado:** en cada medición, a tab imprime o arquivo enteiro. As liñas das medicións engaden o tempo de CPU do terminal e o que levou imprimir: `…, … s of CPU, while printing took … s.` Despois do resumo, `Printing took … s on average, from … to … s.`, e o veredicto sobre ese tempo.

15. **Os resultados non chegan a Git:**

    ```powershell
    Get-ChildItem .perf\scenario-*.csv | Select-Object Name
    git status --short
    ```

    **Resultado esperado:** os CSV dos resumos dos pasos 12, 13 e 14, e ningunha liña de `git status`: todo está en `.perf\`, que está no `.gitignore`.

16. **(Opcional) Cancela unha medición.** Repite o paso 12 e preme Ctrl+C en `run-scenario.ps1` durante unha medición.

    **Resultado esperado:** o script remata sen resumo, e o spinner do Windows Terminal remata só, como moito un segundo despois.
