# Subfase 0.2 · Repositorio público

> **Entrega:** commit inicial, directo a `main`. Era o primeiro commit do repositorio: aínda non había ningunha rama coa que comparar nin CI que executar, polo que non se abriu PR.

## Obxectivo

Crear o repositorio público `NewHouses/meiga` en GitHub e deixalo configurado e protexido antes de escribir código.

## Que se fixo

### 1. Repositorio local e identidade

```powershell
git init -b main
git config user.name NewHouses
git config user.email 78487412+NewHouses@users.noreply.github.com
```

- `git init -b main` crea o repositorio coa rama principal chamada `main`.
- `git config` **sen `--global`** garda os valores só neste repositorio, no arquivo `.git/config`. A configuración global de Git do equipo non cambia.
- O email é o enderezo ***noreply*** que GitHub asigna a cada conta (`<id>+<usuario>@users.noreply.github.com`). GitHub asocia os commits á conta, pero non se publica ningún enderezo de correo real. Isto importa porque nun repositorio público calquera pode ver o email do autor de cada commit.

### 2. Credenciais e remoto

```powershell
git config credential.https://github.com.helper ""
git config --add credential.https://github.com.helper "!gh auth git-credential"
git remote add origin https://github.com/NewHouses/meiga.git
```

- Git obtén as credenciais a través dunha lista de **asistentes de credenciais** (*credential helpers*). A configuración global pode ter outros, como o *Git Credential Manager*, con credenciais doutras contas.
- A primeira liña, cun valor baleiro, **baleira a lista herdada** para as URL de `https://github.com`.
- A segunda engade como único asistente a GitHub CLI (`gh`). O `!` inicial indica que o valor é un comando. `gh` entrega o *token* da súa conta activa ou, se está definida, o da variábel de contorno `GH_TOKEN`.
- Resultado: neste repositorio, `git push` autentícase sempre a través de `gh`, sen depender doutras credenciais gardadas no equipo.

### 4. Configuración en GitHub

| Opción | Valor | Por que |
|---|---|---|
| Visibilidade | Público | O código pódese ver, e as funcións de seguridade de GitHub son gratuítas nos repositorios públicos. |
| Licenza | Ningunha licenza aberta: todos os dereitos reservados | Manter abertas todas as opcións, tamén as comerciais. A licenza decidirase máis adiante. |
| Descrición e temas | `conpty`, `rust`, `terminal`, `terminal-emulator`, `windows` | Que o proxecto se poida atopar. |
| Wiki | Desactivada | A documentación vive en `docs/`. |
| Tipos de *merge* | Só *squash merge* | Cada PR convértese nun único commit en `main`: un historial lineal, cun commit por subfase. |
| Borrar a rama ao integrar | Activado | Non quedan ramas vellas. |
| Alertas de Dependabot | Activadas | GitHub avisa se unha dependencia ten unha vulnerabilidade coñecida. |
| *Secret scanning* | Activado | GitHub busca segredos (*tokens*, contrasinais…) no repositorio. |
| *Push protection* | Activada | GitHub rexeita un *push* que conteña un segredo, antes de que se publique. |
| Notificación privada de vulnerabilidades | Activada | Calquera pode informar dun problema de seguridade sen facelo público. |

As actualizacións automáticas de dependencias con Dependabot (PR semanais) configúranse na subfase 0.4, xunto coa CI.

## Alternativas descartadas

- **Repositorio privado.** Ocultaría o código, pero perderíanse funcións de seguridade que son gratuítas nos repositorios públicos, e os minutos de GitHub Actions serían limitados.
- **Licenza aberta (MIT, Apache-2.0…).** Permitiría a calquera usar o código, tamén nun produto comercial. Mentres non se decida, é mellor non conceder ningún permiso.
- **Usuario na URL do remoto** (`https://NewHouses@github.com/…`), para que o *Git Credential Manager* escollese a conta. Depende de como estea configurado o *Git Credential Manager* en cada equipo. Co asistente de `gh`, a conta depende só da sesión de `gh`.
- ***Merge commits* ou *rebase*.** `main` levaría todos os commits intermedios de cada PR. Con *squash*, cada subfase é un único commit, fácil de ler e de reverter.
- **Wiki de GitHub.** É un repositorio aparte: non se revisa nos PR nin queda ligada a cada versión do código.

## Como comprobalo

```powershell
git config --local --list                 # identidade e credenciais só deste repositorio
git log -1 --format='%an <%ae>'           # o autor usa o email noreply
gh repo view NewHouses/meiga --json visibility,description,repositoryTopics
gh api repos/NewHouses/meiga --jq '{allow_squash_merge, allow_merge_commit, allow_rebase_merge, delete_branch_on_merge, has_wiki, security_and_analysis}'
gh api --include repos/NewHouses/meiga/vulnerability-alerts    # "204 No Content": alertas activadas
gh api repos/NewHouses/meiga/private-vulnerability-reporting   # {"enabled":true}
```

As dúas últimas comprobacións requiren permisos de administración do repositorio.
