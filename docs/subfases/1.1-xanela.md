# Subfase 1.1 · Xanela baleira

> **Entrega:** [PR #7](https://github.com/NewHouses/meiga/pull/7).

## Obxectivo

A primeira peza do programa: unha xanela de Windows que se abre rápido, que non gasta nada mentres non pasa nada e que se pecha limpamente. Leva o manifesto da aplicación, coa escala por monitor (v2), e non abre ningunha consola.

- **Feito cando:** a xanela abre en menos de 50 ms.
- **Medición:** 0 espertares por segundo en repouso. É a primeira porta de rendemento do proxecto.

Sobre esta xanela, a subfase 1.2 engadirá o *framebuffer* e a presentación dos rectángulos que cambian.

## Decisións e alternativas descartadas

| Decisión | Alternativa descartada | Motivo |
|---|---|---|
| Win32 directamente | Un crate de xanelas, como `winit` | Traen o seu propio bucle de eventos e funcións que meiga non necesita. meiga ten que controlar o bucle de mensaxes para cumprir os principios de rendemento: dormir sen temporizadores e, desde a 1.6, espertar só cando unha tab visíbel cambia ([ADR 0002](../adr/0002-windows-e-renderizado-cpu.md), [ADR 0005](../adr/0005-fios-e-fotogramas.md)). |
| `windows-sys` | O crate `windows` | Para unha ducia de funcións Win32, `windows-sys` abonda e compila máis rápido. `windows` chegará coa 1.3, para DirectWrite, unha API COM na que os seus envoltorios aforran moito código delicado. |
| O fondo pintado coa brocha da clase | Pintalo en `WM_PAINT` con `FillRect` | O mesmo resultado con menos código. O *framebuffer* da 1.2 substituirao. |
| Clase sen `CS_HREDRAW` nin `CS_VREDRAW` | Con eles | Farían que Windows repintase a xanela enteira en cada paso dun cambio de tamaño. Sen eles, só se pinta a parte nova. |
| `UpdateWindow` antes do bucle de mensaxes | Deixar que `WM_PAINT` chegue pola cola | O primeiro fotograma está feito antes de esperar mensaxes, e `WaitForInputIdle` mide xusto ata el. |
| `SW_SHOWDEFAULT` | `SW_SHOWNORMAL` | Respecta como se pediu abrir meiga, por exemplo maximizado desde un acceso directo. |
| O manifesto incrustado polo ligador, desde `build.rs` | Un arquivo `.rc` con `embed-resource`, o crate `embed-manifest`, un arquivo xunto ao `.exe` ou chamar a `SetProcessDpiAwarenessContext` | O ligador xa o sabe facer, sen dependencias. Un arquivo á parte pódese perder, e Microsoft recomenda o manifesto antes ca a chamada. Ver [Tecnoloxías › Manifesto](../tecnoloxias.md#23-manifesto-da-aplicación-e-dpi). |
| O `trustInfo` escrito no manifesto, co do ligador desactivado (`/MANIFESTUAC:NO`) | Deixar que o engada o ligador | O que vai dentro do `.exe` é exactamente o que hai no arquivo. |
| Escala *per monitor* v2 | *Per monitor* v1 ou *system aware* | Texto nítido en calquera monitor, e Windows escala a barra de título e os bordos. |
| Só `dpiAwareness` | Tamén o elemento antigo `dpiAware` | `dpiAwareness` funciona desde Windows 10 1607, e meiga necesita a 1809. |
| Unha caixa de mensaxe se meiga non pode arrancar | Só o código de saída | Na compilación *release* non hai consola: sen a caixa, o usuario non vería nada. |
| Os erros de Windows sen código, sen mensaxe do sistema | Mostrar sempre a mensaxe de `GetLastError` | Algunhas funcións fallan sen deixar código, e a mensaxe do código 0 é «The operation completed successfully». |
| `check-window.ps1`, co `meiga.exe` de *release* | Unha proba en Rust que abra unha xanela | Compróbase o mesmo `.exe` que se distribúe, co seu subsistema e o seu manifesto. |
| O arranque medido con `WaitForInputIdle` | Buscar a xanela unha e outra vez ata que apareza, ou ETW | `WaitForInputIdle` é unha función de Windows que espera sen consultar unha e outra vez. Buscar a xanela engadiría atrasos e mediría antes de pintala, e ETW é demasiado para isto. |
| A mediana e o percentil 95 | A media | Un arranque lento, porque o antivirus ou outro programa colleron a CPU nese momento, moveríaa moito. |
| `measure-startup.ps1` na CI, con 3 arranques e sen límite de tempo | Non executalo, ou fallar por riba dun tempo | Os tempos dunha máquina compartida non se comparan con nada; a CI só comproba que o script segue funcionando. |

## Como comprobar que todo está ben

> **Importante: usa PowerShell 7.** Todos os comandos son para PowerShell 7 (`pwsh`), no cartafol do repositorio. Se abres *Windows PowerShell* (a versión 5.1, que trae Windows), os scripts non se executan: só mostran o comando para facelo con `pwsh`. Para saber cal tes aberto, executa `$PSVersionTable.PSVersion`: o primeiro número ten que ser 7.

### No navegador

1. **A CI pasa.** No [PR #7](https://github.com/NewHouses/meiga/pull/7), os tres *checks* en verde: **Build and test (Windows)**, **Load scenarios (bash)** e **Dependency policy (cargo-deny)**.

   **Resultado esperado**, nos pasos de **Build and test (Windows)**:

   - *Check that meiga.exe does not need the Visual C++ runtime*: `meiga.exe imports: kernel32.dll, user32.dll, gdi32.dll, ntdll.dll, api-ms-win-core-synch-l1-2-0.dll, KERNEL32.dll` e `OK: no dependencies on the Visual C++ runtime.`
   - *Check that meiga.exe opens its window and closes it cleanly*: catro liñas que empezan por `OK:`, a última `OK: it ends with exit code 0 when its window closes.`
   - *Check the start-up measurement*: `Starting meiga.exe 1 + 3 times...`, a táboa cos tempos de 3 arranques e `Saved …\.perf\startup-…-meiga.csv`.

### Na túa máquina

2. **Descarga a rama do PR:**

   ```powershell
   git fetch origin
   git switch f1.1-xanela
   ```

3. **Pasa as comprobacións e compila:**

   ```powershell
   cargo fmt --all --check
   cargo clippy --workspace --all-targets -- -D warnings
   cargo test --workspace
   cargo deny check
   .\tools\package.ps1
   .\tools\check-imports.ps1
   ```

   **Resultado esperado:** ningún erro. `cargo test` mostra `test window::tests::colorref_stores_blue_green_red ... ok`; `cargo deny check`, `advisories ok, bans ok, licenses ok, sources ok`; e `check-imports.ps1`, a mesma lista de DLL do paso 1 e `OK: no dependencies on the Visual C++ runtime.`

4. **Abre meiga e pecha a xanela co X:**

   ```powershell
   (Start-Process .\target\release\meiga.exe -Wait -PassThru).ExitCode
   ```

   **Resultado esperado:** ábrese unha xanela co título «meiga» e o fondo gris escuro, sen ningunha consola. Antes de pechala, proba que se comporta como calquera xanela: móvea, cambia o seu tamaño (a parte nova sae escura), maximízaa e minimízaa. Sobre ela, o rato é a frecha normal. Cando a pechas co X, PowerShell mostra `0`, o código de saída.

5. **Comproba a xanela automaticamente:**

   ```powershell
   .\tools\check-window.ps1
   ```

   **Resultado esperado:** a xanela aparece un instante e péchase soa. Na consola, as catro liñas `OK:` do paso 1.

6. **Mide o arranque.** Durante uns 15 s, meiga ábrese e péchase 22 veces: non toques nada.

   ```powershell
   .\tools\perf\measure-startup.ps1
   ```

   **Resultado esperado:** a táboa cos tempos de 20 arranques, en milisegundos, coa **mediana (`median_ms`) por debaixo de 50**, e `Saved …\.perf\startup-…-meiga.csv`. O `p95_ms` e o `max_ms` poden ser bastante máis altos: algún arranque coincide con outro traballo da máquina.

7. **Mide o repouso: a porta de rendemento.** Abre meiga sen esperar a que se peche e mídeo uns 3 minutos e medio, sen tocar nada:

   ```powershell
   Start-Process .\target\release\meiga.exe
   .\tools\perf\run-scenario.ps1 idle -Name meiga
   ```

   **Resultado esperado:**

   - Tres liñas `Window N of 3: the terminal used 0.00 % of one core and 0.0… million cycles per second.`
   - Na táboa, na fila `terminal`: `cpu_pct` **0,00** e `ctx_per_s` (os espertares por segundo) **0,00 ou moi preto**, por exemplo 0,05. Ao arrancar, Windows crea uns poucos fíos auxiliares no proceso, que rematan sós nos primeiros minutos; cada un esperta unha vez para rematar. `private_mb_max`, uns poucos MB.
   - En verde, `Stable: the cycles of the terminal varied … million per second between windows (limit 1.00).`

   Despois, pecha meiga co X.

8. **(Opcional) Mira o manifesto que leva dentro:**

   ```powershell
   $mt = (Get-ChildItem "${env:ProgramFiles(x86)}\Windows Kits\10\bin\*\x64\mt.exe" | Select-Object -Last 1).FullName
   & $mt -nologo '-inputresource:target\release\meiga.exe;#1' "-out:$env:TEMP\meiga.manifest"
   Get-Content "$env:TEMP\meiga.manifest"
   ```

   **Resultado esperado:** o XML do manifesto, nunha soa liña e sen comentarios, con `requestedExecutionLevel level="asInvoker"`, `PerMonitorV2` e `supportedOS Id="{8e0f7a12-bfb3-4fe8-b9a5-48fd50a15a9a}"`. `trustInfo` aparece unha soa vez.

9. **(Opcional) A escala no Xestor de tarefas.** Con meiga aberto, no Xestor de tarefas, lapela *Detalles*: preme co botón dereito na cabeceira dunha columna, *Seleccionar columnas*, e marca *DPI Awareness* (ou o nome equivalente no idioma do teu Windows).

   **Resultado esperado:** na fila de `meiga.exe`, *Per-Monitor (v2)*.

10. **Os resultados non chegan a Git:**

    ```powershell
    git status --short
    ```

    **Resultado esperado:** ningunha liña. Os CSV dos pasos 6 e 7 están en `.perf\`, que está no `.gitignore`.

## Pendente

- **A barra de título** é a estándar de Windows, clara, aínda que o sistema estea en modo escuro. A propia de meiga chegará na subfase 2.9, e o tema, na 8.3. A icona tamén é a xenérica de Windows.
- **O cambio de escala entre monitores** só se probou co código que o trata: nesta máquina só hai un monitor. Os cambios de escala completos, coas fontes, chegan na 1.9.
- **A pila de entrada de texto de Windows.** Serve para os métodos de entrada (por exemplo, para escribir en chinés) e para o panel de emoji (Win+.). Decidirase na 1.7, co teclado, se se mantén.
- **`SegmentHeap`.** Un axuste do manifesto que fai que Windows use un xestor de memoria máis moderno, que pode usar menos memoria. Probarase con medicións na subfase 9.3, xunto co asignador de memoria.
