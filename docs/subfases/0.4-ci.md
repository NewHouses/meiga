# Subfase 0.4 · Integración continua

> **Entrega:** [PR #2](https://github.com/NewHouses/meiga/pull/2).

## Obxectivo

Que cada PR se valide automaticamente nunha máquina limpa, e que ningún cambio poida chegar a `main` sen pasar esa validación.

## Decisións e alternativas descartadas

| Decisión | Alternativa descartada | Motivo |
|---|---|---|
| GitHub Actions | Outros servizos de CI | Está integrado no repositorio e é gratuíto nos repositorios públicos. |
| Actions fixadas por SHA | Etiquetas (`@v7`) | Unha etiqueta pódese mover a outro commit. Ver [Tecnoloxías › Seguridade do workflow](../tecnoloxias.md#seguridade-do-workflow). |
| `rustup toolchain install` | Unha action de terceiros para instalar Rust | rustup xa vén nos runners e le `rust-toolchain.toml`. Ademais, algunha desas actions define `RUSTFLAGS` por defecto, o que anularía o `+crt-static`. |
| Runners con versión fixada (`windows-2025`, `ubuntu-24.04`) | `windows-latest`, `ubuntu-latest` | Un cambio de imaxe non pode romper a compilación sen un PR. A contrapartida é actualizalas a man cando GitHub as retire. |
| `cargo-deny` en Linux, en paralelo | Todo nun único job de Windows | O resultado é o mesmo, as máquinas Linux arrancan antes e os dous jobs corren á vez. |
| Ferramentas xa compiladas e verificadas | `cargo install` na CI | Compilalas levaría varios minutos en cada execución. |
| Zip subido tal cal (`archive: false`) | Subir os arquivos sen comprimir | O artefacto é exactamente o zip que xera o script, sen un zip dentro doutro. |
| Caché gardada só desde `main` | Gardala tamén en cada PR | A caché dun PR só lle serve a ese PR e ocupa espazo do límite de 10 GB. |
| *Ruleset* | Protección de ramas clásica | É o mecanismo que recomenda GitHub e permite esixir que os *checks* veñan de GitHub Actions. |
| Sen aprobacións obrigatorias | Esixir unha aprobación | En GitHub, o autor dun PR non pode aprobalo, e é o propietario quen abre os PR: bloquearíase todo. |
| Espera de 7 días en Dependabot | Propor as versións no momento | Protexe de versións maliciosas ou rotas, que adoitan retirarse nos primeiros días. |
| Comprobación automática das DLL | Confiar en `.cargo/config.toml` | Unha variábel `RUSTFLAGS` desfai o CRT estático sen que nada falle. Comprobouse. |

## Como comprobar que todo está ben

### No navegador

1. **A CI pasa no PR.** Abre o [PR #2](https://github.com/NewHouses/meiga/pull/2) e baixa ata a caixa dos *checks*, ao final da conversa.

   **Resultado esperado:** "All checks have passed", con dous *checks* en verde: **Build and test (Windows)** e **Dependency policy (cargo-deny)**.

2. **O artefacto contén o programa.** Preme en *Details* ao carón de **Build and test (Windows)** e, no menú da esquerda, en *Summary*. Na sección *Artifacts*, descarga `meiga-0.1.0-x86_64-pc-windows-msvc.zip`.

   **Resultado esperado:** o zip contén catro arquivos: `meiga.exe`, `LICENSE.txt`, `README.md` e `THIRD-PARTY-NOTICES.txt`.

3. **O programa arranca e sae ben.** Descomprime o zip e, nunha consola de PowerShell nese cartafol:

   ```powershell
   (Start-Process .\meiga.exe -Wait -PassThru).ExitCode
   ```

   **Resultado esperado:** `0`, sen ningunha xanela, porque polo de agora o programa só arranca e sae. Windows pode avisar de que o arquivo vén de Internet: é normal, porque o executábel aínda non está asinado.

4. **As regras de `main` están activas.** En *Settings* → *Rules* → *Rulesets* ([ligazón](https://github.com/NewHouses/meiga/settings/rules)), abre o *ruleset* `main`.

   **Resultado esperado:** *Enforcement status: Active*, a lista de excepcións (*Bypass list*) baleira e as regras da táboa de [Tecnoloxías › Regras de `main`](../tecnoloxias.md#17-regras-da-rama-main-rulesets).

5. **Dependabot está activo.** En *Settings* → *Advanced Security*, mira a sección *Dependabot*.

   **Resultado esperado:** *Dependabot alerts* e *Dependabot security updates* activados. Despois de integrar o PR, a páxina de [actualizacións de Dependabot](https://github.com/NewHouses/meiga/network/updates) mostra os tres ecosistemas (`cargo`, `github-actions` e `rust-toolchain`) coa data da última revisión.

### Na túa máquina

Todos os comandos son para PowerShell 7, no cartafol do repositorio.

6. **Descarga a rama do PR:**

   ```powershell
   git fetch origin
   git switch f0.4-ci
   ```

7. **Crea o paquete:**

   ```powershell
   .\tools\package.ps1
   ```

   **Resultado esperado:** a última liña é `Wrote …\dist\meiga-0.1.0-x86_64-pc-windows-msvc.zip`.

8. **Comproba as DLL:**

   ```powershell
   .\tools\check-imports.ps1
   ```

   **Resultado esperado:**

   ```text
   meiga.exe imports: api-ms-win-core-synch-l1-2-0.dll, KERNEL32.dll, ntdll.dll
   OK: no dependencies on the Visual C++ runtime.
   ```

9. **(Opcional) Comproba que o script detecta o problema.** Compila nun cartafol aparte con `RUSTFLAGS`, que anula o CRT estático:

   ```powershell
   $env:RUSTFLAGS = '-C opt-level=3'
   cargo build --release --target-dir target\rustflags-test
   Remove-Item Env:RUSTFLAGS
   .\tools\check-imports.ps1 -Path target\rustflags-test\release\meiga.exe
   ```

   **Resultado esperado:** un erro que empeza por `It depends on the Visual C++ runtime: VCRUNTIME140.dll, …`.

10. **Un *push* directo a `main` é rexeitado:**

    ```powershell
    git switch main
    git pull
    git commit --allow-empty -m "Test: direct push to main"
    git push origin main
    ```

    **Resultado esperado:** o *push* falla cunha mensaxe que empeza por `GH013: Repository rule violations found for refs/heads/main` e indica que os cambios deben entrar por un PR. Despois, borra o commit de proba, que só existe no teu equipo:

    ```powershell
    git reset HEAD~1
    ```
