# ADR 0001 · Rust como linguaxe

- **Estado:** Aceptado
- **Data:** 2026-11-06
- **Relacionados:** [ADR 0003](0003-nucleo-vt-alacritty-terminal.md), [ADR 0006](0006-licenzas-e-dependencias.md)

## Contexto

meiga é un terminal para Windows no que o rendemento (CPU e memoria) é a prioridade número 1. A linguaxe condiciona varias cousas:

- **O custo en execución.** Un recolector de lixo (*garbage collector*) engade pausas e memoria extra, e un *runtime* pesado engade fíos e tempo de arranque. Os dous poden facer espertar a CPU aínda que o programa non teña traballo.
- **A seguridade.** Un terminal procesa todo o texto que escriben os programas, tamén texto malicioso, como secuencias de escape manipuladas. Un erro de memoria nese camiño pode converterse nunha vulnerabilidade.
- **O acceso a Windows.** Hai que chamar directamente a Win32, DirectWrite, GDI e ConPTY.
- **O ecosistema.** Reutilizar un núcleo de terminal xa probado aforra meses de traballo ([ADR 0003](0003-nucleo-vt-alacritty-terminal.md)).
- **O equipo.** Unha soa persoa: canto máis erros detecte o compilador, mellor.

## Decisión

Usamos **Rust**, edición 2024, cunha versión do compilador fixada en `rust-toolchain.toml`. Cada cambio de versión chega nun PR propio, que pasa pola CI.

- A lóxica que non depende de Windows vai en `meiga-core`, que prohíbe o código `unsafe` con `#![forbid(unsafe_code)]`.
- O código `unsafe` necesario para chamar a Windows limítase a `meiga-win` e `meiga-render`, e cada bloque explica nun comentario `// SAFETY:` por que é seguro.
- Para as APIs de Windows úsanse os crates oficiais de Microsoft: `windows` e `windows-sys`.

## Alternativas consideradas

| Alternativa | Por que se descarta |
|---|---|
| C++ | Mesmo rendemento e acceso directo a Windows, pero sen seguridade de memoria: os erros só se descobren en execución, se se descobren. |
| C | Os mesmos problemas ca C++, e menos ferramentas para organizar un programa grande. |
| Zig | Rendemento comparábel, pero un ecosistema moito máis pequeno: sen núcleos de terminal maduros e con menos soporte para Windows. |
| C# / .NET | Recolector de lixo, máis memoria e arranque máis lento. A compilación nativa (AOT) mellora o arranque, pero mantén o recolector. |
| Go | Recolector de lixo e un *runtime* que xestiona os seus propios fíos: menos control sobre a memoria e sobre cando esperta a CPU. |
| Electron ou tecnoloxías web | Un navegador completo: varios procesos e centos de MB de memoria. É xusto o que meiga quere evitar. |

## Consecuencias

**Positivas:**

- Rendemento de linguaxe nativa, sen pausas de recolección de lixo.
- No código seguro, que será a maior parte, o compilador impide os erros de memoria e os *data races*.
- Acceso completo a Windows cos crates oficiais.
- Podemos reutilizar `alacritty_terminal` ([ADR 0003](0003-nucleo-vt-alacritty-terminal.md)).

**Negativas e riscos:**

- Compilar leva máis tempo ca noutras linguaxes, sobre todo en *release* con LTO. Mitigación: catro crates separados e compilación incremental durante o desenvolvemento.
- Chamar a Windows require `unsafe`. Mitigación: illado en dous crates, con cada bloque documentado; os *lints* esíxeno.
- Unha versión nova de Rust pode traer *lints* novos que fallen na CI. Mitigación: versión fixada e actualizacións en PR propios, que propón Dependabot.
